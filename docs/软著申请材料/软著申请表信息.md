## 五、软件用途说明

FnixAgent 智能工作台系统 V1.0 是一款**本地优先（Local-First）的 AI Agent 客户端工作台软件**，面向个人办公、学习辅助和本地编程场景，将大语言模型（LLM）能力接入用户本机，提供开箱即用的智能任务执行体验。

软件采用 **BYOK（Bring Your Own Key，用户自带 API Key）** 架构，软件本身不提供任何 AI 模型服务，仅作为客户端调用用户自行配置的第三方大语言模型 API 接口。用户需自行前往 LLM 服务商（如 OpenAI、阿里通义千问 Qwen、智谱 GLM、DeepSeek 等）获取 API Key 并在本地配置，软件在用户主动发起请求时将输入内容经加密通道传输至用户配置的 LLM API 端点，并接收返回结果呈现给用户。

软件提供两大核心工作模式：

1. **Work 模式（办公任务）**：通过自然语言描述任务需求，Agent 自动进行意图识别、任务规划、工具调用与产物生成，最终输出 Word 文档（.docx）、Excel 表格（.xlsx）、PDF 报告、图表、Markdown 文件等多种可下载的办公产物。适用于周报撰写、数据分析、文献检索、格式转换、文档解析等办公场景。

2. **Code 模式（编程辅助）**：面向本地编程项目的智能辅助，Agent 自动分析需求、生成修改计划、执行代码修改并自我审查。通过 `@file` 语法引用项目文件，以 Diff 差异预览方式展示代码变更，用户确认（Accept）后写入磁盘。适用于代码重构、Bug 修复、功能开发、代码审查等编程场景。

软件适用于个人开发者、研究人员、学生、知识工作者等用户群体，满足其在本地环境下进行智能办公与编程辅助的需求。

## 六、软件功能与特点描述

### 6.1 技术架构

FnixAgent 采用**三进程架构**设计，各进程职责明确、独立运行，通过 HTTP 协议进行通信：

```
Desktop (Tauri 2)  →  agentd :8003  →  fnix-local :8710
        ↘ ~/.fnix + {workspace}/.fnix
```

- **Desktop（Tauri 2）**：桌面前端 UI，基于 Rust 的 Tauri 2 框架构建，负责 Work/Code 界面渲染、IPC 通信、伪终端（PTY）管理、BYOK 密钥设置界面、本地文件系统交互。前端采用 React 19 + TypeScript + Tailwind CSS 4 技术栈，内置 Monaco Editor 代码编辑器与 xterm.js 终端模拟器。

- **agentd（端口 8003）**：Python 后端服务，是系统的"大脑"。基于 FastAPI 异步框架构建，负责 KTG/STP/MFP 自进化引擎运转、Work 与 Code 任务的核心调度编排、LLM 调用路由、记忆管理、安全校验。采用 LangGraph 进行 Agent 工作流编排，支持 ReAct、Plan&Execute、Self-Reflection 三种可插拔推理模式。

- **fnix-local（端口 8710）**：Rust 编写的本地算力 sidecar 进程，负责项目文件索引、程序依赖图（PDG）构建、沙箱命令执行。fnix-local 离线时 Work/Code 可降级使用 Python 内置工具继续运行，保证核心功能可用性。

在纵向分层上，系统采用**七层架构**设计：

| 层级 | 名称 | 职责 |
|------|------|------|
| 第 1 层 | UI 层 | 用户界面渲染与交互，基于 React 19 + Tauri WebView |
| 第 2 层 | API 层 | RESTful API 接口与 SSE 事件流，基于 FastAPI |
| 第 3 层 | 编排层 | Agent 工作流编排，基于 LangGraph，支持三模式推理 |
| 第 4 层 | 推理层 | LLM 调用路由与推理执行，支持多提供商故障转移 |
| 第 5 层 | 工具层 | 工具注册、权限分级、沙箱执行 |
| 第 6 层 | 知识层 | KTG 知识拓扑图、STP 技能突触、记忆管理 |
| 第 7 层 | 存储层 | SQLite 本地数据库、文件系统持久化、加密存储 |

### 6.2 核心模块

#### 6.2.1 Work 模式 — 办公任务流式执行

Work 模式采用 9 步流水线执行办公任务，通过 `POST /api/v1/work/stream` 接口提供流式服务：

1. 安全校验（敏感词检测、Prompt 注入防护）
2. 短期记忆加载（滑动窗口对话历史）
3. 长期/实体记忆召回（向量检索、用户画像）
4. 推理模式选择（ReAct / Plan&Execute / Self-Reflection 自动选择）
5. KTG 路径搜索 + STP 技能排序
6. AgenticLoop 工具执行（流式循环：推理→选工具→沙箱执行→观察）
7. 反思提示注入（Self-Reflection 模式下校验结果完整性）
8. 输出审核与脱敏（内容审核、敏感信息脱敏）
9. 记忆保存 + MFP 进化 + KTG 快照 + TraceId 审计

支持产出 Word 文档（.docx）、Excel 表格（.xlsx）、PDF 报告、图表（柱状图/折线图/饼图/散点图/热力图）、Markdown 文件等多种格式产物，并提供 docx/pdf/markdown/html/txt 多种格式互转、PDF/Word/图片文档解析（含 OCR 多模态识别）、arXiv/Semantic Scholar/知网文献检索等功能。

#### 6.2.2 Code 模式 — 编程辅助 Diff 预览

Code 模式采用"Diff 预览 → Accept 写盘"的安全交互模式，确保用户对代码变更拥有完全审查与控制权。通过 `POST /api/v1/chat/agent` 接口提供服务，工作流程为：规划阶段（分析需求生成修改计划）→ 执行阶段（逐步生成修改并输出 Diff 预览）→ 审查阶段（Agent 自动检查语法正确性与逻辑一致性）→ 用户确认（Accept 写入磁盘 / Reject 放弃修改）。

支持 `@file` 语法引用项目文件，输入 `@` 后自动弹出文件选择列表支持模糊搜索，可同时引用多个文件或目录。fnix-local 构建项目程序依赖图（PDG），为 Agent 提供精确的代码结构上下文。

#### 6.2.3 Harness — 基础设施管理

Harness 负责会话持久化、工作区管理、MCP 配置与项目技能管理：

- **会话持久化**：所有 Work 与 Code 会话自动持久化至 `~/.fnix/sessions/` 目录，重启后可恢复历史会话。
- **工作区管理**：打开工作区文件夹时自动初始化 `.fnix/` 目录结构，触发 fnix-local 构建项目文件索引（PDG），加载项目技能与规则文件。
- **MCP 配置**：支持通过 Model Context Protocol 扩展 Agent 工具能力，配置存储于 `~/.fnix/mcp.json`，支持热加载。
- **项目技能（Skills）**：以 Markdown 文件形式存储项目特定指令与知识，通过 STP 注入 Agent 推理过程，支持热加载。

#### 6.2.4 安全模块 — 六道安全关卡

构建纵深防御安全体系，覆盖从输入到输出的全链路安全管控：

1. **网关鉴权（JWT）**：HS256 算法，令牌默认 24 小时有效期，验证请求合法性。
2. **输入安全引擎**：敏感词检测（8 大类词库，三级检测）+ Prompt 注入攻击防护（最大尝试限制 3 次）。
3. **工具权限分级**：工具按 low/middle/high 三级权限分类，high 级别工具需额外确认。
4. **沙箱隔离执行**：动态代码在安全沙箱中执行，限制文件系统访问范围与系统调用，执行超时 10 秒，网络白名单机制。
5. **输出审核与脱敏**：内容合规性检查 + 敏感信息脱敏（邮箱/手机号/身份证号）。
6. **审计落库**：全链路 TraceId 追踪，所有工具调用与安全事件记录至审计日志。

采用 Argon2id（密码哈希）+ RSA（非对称加密）+ AES-256-GCM（对称加密）+ PBKDF2-SHA256（密钥派生，100,000 次迭代）三层加密体系保护敏感数据。

#### 6.2.5 AG-UI 协议 — SSE 事件流

基于 Server-Sent Events（SSE）协议的实时事件流推送机制，通过 `POST /api/v1/ag-ui/work/stream` 接口返回 NDJSON 格式的流式事件。事件类型包括：evolution（自进化状态）、pipeline（流水线步骤）、thought（思考过程）、action（工具调用）、artifact（产物生成）、done（任务完成）。前端实时渲染 Agent 执行过程，包括步骤条进度、打字机效果思考过程、工具调用卡片、产物即时预览。

#### 6.2.6 自进化内核 — KTG/STP/MFP 三大机制

自进化内核是本软件区别于传统 LLM Agent 的核心差异化能力，由三大原创机制构成：

- **KTG（Knowledge Topology Graph，知识拓扑图）**：构建四层知识拓扑结构（概念层、技能层、工具层、资源层），节点间通过带权重的边连接，通过权重路径搜索（Top-K=3，最大深度=6，剪枝阈值=0.05）替代传统纯向量 RAG 检索方式，提升知识召回精度。拓扑图快照持久化至 `data/topology/` 目录。

- **STP（Skill-Topology Synapse Protocol，技能突触协议）**：建立概念层与技能之间的突触连接，通过权重驱动工具的优先级排序，使系统能根据任务上下文动态调整工具选择策略。

- **MFP（Multi-stage Flywheel Protocol，四阶进化飞轮）**：四阶段持续进化循环，在用户日常使用中自动运行：阶段 1 感知执行（每次对话，最大迭代 5 次）→ 阶段 2 知识固化（每次对话，过滤垃圾信息）→ 阶段 3 元反思（每 10 次对话，识别改进空间）→ 阶段 4 爬山进化（每 50 次对话，优化拓扑权重，进化前自动快照）。所有持久化资产启用 AES-256-GCM 加密存储。

### 6.3 技术特点

1. **本地优先架构**：用户全部数据存储于本地文件系统，不上传至任何服务器，遵循"数据本地化、模型服务化、责任用户化"设计理念。

2. **BYOK 模式**：软件不内置任何 LLM 服务，用户自带 API Key 接入第三方模型服务，密钥加密存储于本地 `~/.fnix` 目录，支持多提供商配置与故障转移。

3. **三进程解耦架构**：Desktop、agentd、fnix-local 三进程独立运行，职责明确，fnix-local 离线时系统可降级运行，保证核心功能可用性。

4. **自进化能力**：KTG/STP/MFP 三大机制使系统能够在使用过程中持续学习、优化推理路径与工具选择策略，实现"越用越聪明"的进化效果。

5. **纵深安全防御**：六道安全关卡覆盖全链路，三层加密体系保护敏感数据，沙箱隔离执行防止恶意代码逃逸。

6. **跨平台支持**：基于 Tauri 2 框架，同时支持 Windows、macOS、Linux 三大主流操作系统，支持 x64 与 ARM64 硬件架构。

7. **流式实时交互**：基于 SSE 协议的 AG-UI 事件流，前端实时展示 Agent 思考过程、工具调用、产物生成，提供透明可观测的任务执行体验。

8. **AI 合规设计**：AI 生成内容标识机制遵循《生成式人工智能服务管理暂行办法》第十二条规定，在文件元数据中标注"由 AI 辅助生成"标识。

## 九、软件技术特点总结

本软件的主要技术特点与创新点如下：

1. **三进程解耦架构**：采用 Tauri Desktop → Python agentd → Rust fnix-local 的三进程架构，各进程职责明确、独立运行，支持降级运行保证可用性。

2. **七层分层架构**：UI 层 → API 层 → 编排层 → 推理层 → 工具层 → 知识层 → 存储层，层次清晰，职责分明。

3. **自进化内核**：原创 KTG（知识拓扑图）、STP（技能突触协议）、MFP（四阶进化飞轮）三大机制，实现系统在使用中持续学习与优化。

4. **本地优先与 BYOK 架构**：数据本地化存储，用户自带 API Key，软件不提供模型服务，保障数据安全与用户控制权。

5. **六道安全关卡**：JWT 鉴权、输入安全、工具分级、沙箱执行、输出审核、审计落库，构建纵深防御安全体系。

6. **AG-UI 实时事件流**：基于 SSE 协议的结构化事件流，提供透明可观测的任务执行体验。

7. **跨平台跨架构**：基于 Tauri 2 框架，支持 Windows/macOS/Linux 三大操作系统与 x64/ARM64 双架构。
