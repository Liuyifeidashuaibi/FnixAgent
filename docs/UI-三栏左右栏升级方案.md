# Fnix Workbench · 左右栏 UX 升级方案

> 日期：2026-07-31 · 状态：方案待评审（未实施）
> 范围：三栏布局的**左栏**（会话/项目导航）与**右栏**（StudioPanel 工作台面）
> 基准：中栏（ChatHead + MessageList + Composer + ProcessTimeline）已升级完成，本方案以其设计语言为对齐基准
> 原则：美观 · 极简 · 方便 — 以**真实用户体验**与**工具效率**为根本评估标准

---

## 一、背景与现状

### 1.1 三栏结构

```
┌─────────────┬──────────────────────────┬──────────────┐
│  左栏 oai-side  │     中栏 oai-main            │ 右栏 fnx-studio │
│  (导航/会话)    │  (对话/Composer)             │ (检查器/工件)   │
└─────────────┴──────────────────────────┴──────────────┘
```

- **左栏** `aside.oai-side`：ProductSegment(Work/Code) + 收起按钮 → 新任务按钮 → 搜索 → 仓库区(oai-proj-rail) → 会话列表(ThreadSidebar) → 底部(设置+诊断)
- **中栏** `main.oai-main`：ChatHead + MessageList + ProcessTimeline + Composer dock（**已升级**）
- **右栏** `aside.fnx-studio`：StudioPanel — tabs(canvas/results/review/terminal/browser) + 可拖拽调宽 + 关闭

### 1.2 已有的 2026-07-23 CSS 层

`tokens.css` 末尾存在一段 "REDESIGN 2026-07-23 · 三栏极简统一层"，对左右栏做了**纯视觉**抛光（发丝边框、软胶囊 tab、hover 态、圆角节奏）。但这只是 CSS 覆盖层——**组件结构、信息架构、交互逻辑均未升级**。这正是"左右两边还没升级"的真实含义：视觉有了底子，但 UX 深度不够。

### 1.3 中栏已建立的设计语言（对齐基准）

| 维度 | 中栏做法 |
|------|---------|
| 顶部工具栏 | ChatHead — 一行 icon buttons，右侧聚合操作（jobs/skills/inspector/project/newChat） |
| 操作可见性 | 默认极简，hover/active 才显次要操作（渐进式披露） |
| 模式强调色 | Work=绿 #10a37f / Code=紫 #7c3aed，`--accent` 跟随 `data-mode` |
| 状态指示 | badge 计数 + 风险色点（low/medium/high）+ live 呼吸点 |
| 留白节奏 | 8px 基线，圆角 8-10px，发丝边框 `rgba(0,0,0,0.06)` |
| 动效 | `--dur-1`/`--dur-2` + `--ease-soft`，prefers-reduced-motion 降级 |

## 二、联网调研结论

> 来源：Cursor 2.0 侧栏体系、ChatGPT pinned chats & projects、Claude Code 侧栏改版、Split-Screen Agent 模式(Cursor/Replit/Copilot)、渐进式披露 UX 研究、chatbot UI 12 模式分析

### 2.1 行业共识模式

1. **Split-Screen Agent（2025 主流）**：左=意图/对话，右=产物/结果。产品已采用，方向正确。
2. **会话历史可扩展**（ChatGPT 核心模式）：自动命名 + 搜索 + **置顶(pin)** + 项目分组。ChatGPT 2026-06 刚上线 pinning，证明这是高频刚需——"用户回访历史会话的频率比想象中早得多"。
3. **渐进式披露**：复杂度按需展开，层级 < 3。减少认知负荷最高 40%、错误率 30%。
4. **hover 行内操作**：从右侧滑入，active 行不常驻（去噪）——产品已部分实现。
5. **可见上下文**（Copilot 模式）：明确展示当前作用域（哪个仓库/文件在范围内）。
6. **propose-then-apply 审查环**（Cursor 模式）：右栏 Review 已实现，是"对话→不可逆操作"之间的必要桥梁。
7. **空态即入口**：干净的空态 = 引导新用户的第一步，而非"什么都没有"。

### 2.2 关键判断

- **Claude Code 侧栏改版**的量化结论：任务切换效率 73%、会话连续性 81%、多文件导航 79%——侧栏是效率核心，值得投入。
- **Sidebar 消失 = AI 使用率下降**：Cursor 用户反馈"修好侧栏位置后 AI 使用率提升 150%"——侧栏可见性直接影响工具被使用的频率。

## 三、设计原则

1. **先减后加**——每个元素必须回答"它提高效率吗？"，否则删。极简不是少做，是不做没用的事。
2. **中栏对齐**——左右栏的圆角、间距、hover 态、强调色、按钮形态全部与中栏同源，消除"三个时代"的割裂感。
3. **渐进式披露**——次要操作 hover 才现，主操作永远可达；信息层级 ≤ 2。
4. **状态可感知**——当前在哪（选中态）、在做什么（live/badge/dot）、能做什么（空态引导）三秒内可读。
5. **键盘可达**——所有核心操作有快捷键，焦点可见（WCAG 2.2）。
6. **不引入新依赖**——用现有 lucide-react + CSS 变量体系，不增包体积。

## 四、左栏升级方案

### Spec L1：会话置顶（Pinning）✅ 必要

**评估**：会话数量增长后，正在跟进的任务被时间分组淹没。ChatGPT/ChatGPT-app 2026-06 上线 pinning 证明这是 #1 组织诉求。**保留价值高、实现成本低、无副作用。**

**设计**：
- ThreadSidebar 顶部新增「置顶」分区（仅当有置顶项时渲染，无则不占位——极简）。
- 会话行 hover 操作区增加 Pin/Unpin 按钮（图钉图标 `Pin` / `PinOff`），与重命名/删除同列。
- 置顶项不参与时间分组，固定在列表最上方，按置顶时间倒序。
- 置顶状态持久化到 `sessionStore`（与现有 rename/delete 同存储路径）。
- 视觉：置顶行左侧 2px 模式色竖条（`--accent`），与普通行做轻量区分，不加背景色（避免选中态冲突）。

### Spec L2：项目—会话关系重组 ✅ 必要

**评估**：当前"仓库区"(oai-proj-rail) 和"会话列表"(ThreadSidebar) 是两个独立区块，会话不按项目分组。多项目并行时会话混杂，找不回上下文。**这是效率瓶颈，必须修。**

**设计**：
- 保留仓库区作为"项目切换器"（当前选中项目高亮）。
- 会话列表默认按**当前项目**过滤显示（顶部一行小字提示「仓库 · {projectLabel}」，可点击切换"全部会话"）。
- 当切换到"全部会话"视图时，会话按项目分组，每组带项目色点 + 项目名标题（复用 oai-proj-ico 配色）。
- 分组头可折叠（渐进式披露），折叠状态持久化。
- **不做**复杂的多级树（层级 > 2 违反原则），只做"项目 → 会话"两层。

### Spec L3：空态升级 ✅ 必要

**评估**：当前空态是纯文字 hint（"开始一个新任务"），无引导、无操作入口。空态是新用户第一印象，也是回访用户的"从哪开始"锚点。**升级成本低，体验收益高。**

**设计**：
- 无会话时：居中图标瓷砖（复用 `fnx-studio-empty` 的圆角瓷砖样式）+ 主文案 + 一行辅助文案 + 主操作按钮（"新任务"）。
- 无项目时：FolderOpen 图标 + "打开一个仓库开始" + 打开按钮。
- 搜索无结果时：保留当前"没有匹配"文案，加"清除搜索"快捷链接。

### Spec L4：底部栏精简 ✅ 必要（微调）

**评估**：当前底部"设置(带状态点) + 诊断"已较紧凑。但状态点语义不够清晰（ok/bad/checking 三态只用颜色）。

**设计**：
- 状态点增加 `title` 已有，补充：离线时设置行整行加 `--bad` 色的左侧 2px 竖条（与置顶行同语言），一眼可辨。
- 诊断按钮(Activity 图标)保留——低频但必要，放角落合理。
- **不增加**模型名显示（中栏 FnixStatusBar 已有，避免重复信息）。

### Spec L5：视觉对齐中栏 ✅ 必要

**评估**：2026-07-23 CSS 层已做基础对齐，但仍有细节割裂。

**设计**：
- 新任务按钮：与中栏 Composer 的主操作同圆角(10px)、同阴影(`--elev-1`)、同 hover 过渡。
- 会话行：统一 8px 圆角、hover `rgba(0,0,0,0.04)`、active `rgba(0,0,0,0.065)`——已有，确认无回退。
- 分区标题：11.5px / 550 字重 / `--faint`——已有，确认无回退。
- icon buttons 统一用 `oai-ibtn sm` 体系（24×24，圆角 6px），与 ChatHead 的 icon buttons 同语言。

### Spec L6：键盘导航增强 ✅ 必要（低成本）

**评估**：当前有 Ctrl+K 搜索、Ctrl+B 侧栏。但会话列表本身不可键盘遍历。

**设计**：
- 会话列表容器加 `role="listbox"`，行加 `role="option"`。
- 上/下方向键在会话间移动焦点（不自动打开，Enter 才打开）——避免误触。
- 焦点环复用全局 `focus-visible` 规则，无需新样式。

## 五、右栏升级方案（StudioPanel）

### Spec R1：面板头部上下文化 ✅ 必要

**评估**：当前头部只有 tabs + 关闭按钮，缺乏"我在看什么"的上下文。切换 tab 后无标题，新用户不知道当前视图的含义。

**设计**：
- tabs 下方（或 tab 内）增加一行轻量上下文条：当前 tab 名 + 关键计数（如 Review 显示"N 个变更 · M 个高风险"，Canvas 显示"钉选 N 项"）。
- 上下文条用 12px / `--faint`，不抢视觉。
- 仅在有内容时显示，空态时不渲染（极简）。

### Spec R2：分 tab 空态 ✅ 必要

**评估**：当前 `fnx-studio-empty` 是通用空态。但不同 tab 的"空"含义不同：Canvas 空=还没钉选产物；Review 空=没有待确认变更；Terminal 空=智能体尚未执行。

**设计**：
- 每个 tab 的空态有独立主文案 + 辅助文案 + 引导动作（如 Review 空态："没有待确认的变更" + "在对话中让智能体修改代码"）。
- 复用圆角瓷砖图标样式，仅文案差异化。
- **评估后不做**：不在空态放操作按钮（操作入口在中栏对话，右栏是结果展示面，避免制造歧义入口）。

### Spec R3：tab 操作前置（可选，谨慎）⚠️ 需评审

**评估**：Review 的 Accept All / Reject 在视图内部；Canvas 的 pin 在视图内部。是否把高频操作提到头部？**倾向不做**——头部已有 tabs+关闭，再加操作会让密度过高，违反极简。操作留在视图内更符合"上下文即操作"。

**结论**：**不做**。保持头部纯净。如未来某操作被验证为"每次开面板都要点"，再前置。

### Spec R4：视觉对齐中栏 ✅ 必要

**设计**：
- 面板左边框：发丝 `1px solid var(--border)`（已有）。
- 头部高度 46px——与中栏 ChatHead 视觉等高（如 ChatHead 非 46px，取两者一致值）。
- tab 软胶囊：选中 `rgba(0,0,0,0.06)` + `--text`，hover `rgba(0,0,0,0.045)`——已有，确认。
- tab 图标选中时染 `--accent`——已有。
- 暗色主题分支已有，确认无遗漏。

### Spec R5：拖拽手柄体验 ✅ 已较好（微调）

**评估**：当前 8px 热区 + hover 露出 2px 模式色，双击复位。体验已不错。

**设计**：
- 仅补充：拖拽中 `body.fnx-studio-resizing` 时禁用文本选择（确认已有 `user-select:none`）。
- 双击复位的 `title="拖拽调整宽度 · 双击复位"` 已有——保留。

### Spec R6：关闭后的恢复入口 ✅ 必要

**评估**：右栏关闭后，只能靠 ChatHead 的 inspector 按钮恢复。但无会话时（首页态）没有 ChatHead，关闭后无入口。

**设计**：
- 类比左栏的 `oai-side-expand`，右栏关闭后在右边缘提供悬浮展开入口（仅无 ChatHead 场景）。
- 复用 `oai-side-expand` 样式语言，镜像到右侧。

## 六、不做清单（明确剔除）

| 候选 | 决定 | 理由 |
|------|------|------|
| 会话文件夹/多级树 | ❌ 不做 | 层级 > 2，违反渐进式披露；项目分组已够 |
| 会话标签/彩色标记 | ❌ 不做 | 增加管理负担，pinning + 项目分组已覆盖组织需求 |
| 右栏多面板分屏 | ❌ 不做 | 三栏已占满宽度，再分会屏挤占对话区 |
| 侧栏可拖拽调宽 | ❌ 不做 | 260px 固定宽度已是 ChatGPT/Cursor 验证过的舒适值；可调宽增加复杂度无收益 |
| 模型选择器进左栏底部 | ❌ 不做 | 中栏 Composer slot + FnixStatusBar 已有，重复 |
| 右栏头部加面包屑导航 | ❌ 不做 | tab 名 + 计数已足够，面包屑是 Web 思维不适合桌面端 |

## 七、视觉对齐规范（左右栏统一）

```
圆角:    行/按钮 8px · 主按钮/瓷砖 10px · icon按钮 6px
间距:    8px 基线 · 分区间 14px 上 6px 下
边框:    1px solid var(--border)  [rgba(0,0,0,0.06)]
hover:   rgba(0,0,0,0.04) ~ 0.045
active:  rgba(0,0,0,0.06) ~ 0.065
字重:    标题 550 · 正文 400 · 强调 600
字号:    分区标题 11.5px · 行文案 13px · 辅助 12px · 徽章 10px
强调色:  --accent 跟随 data-mode (work=绿/codex=紫)
动效:    --dur-1(150ms) · --ease-soft · reduced-motion 降级
暗色:    所有 rgba(0,0,0,*) 对称替换为 rgba(255,255,255,*)
```

## 九、预期收益

- **效率**：pinning + 项目分组让"找回上下文"从滚动翻找 → 一眼定位（预计节省每次 15-30s）
- **体验**：左右栏与中栏视觉统一，消除"三个时代"割裂感
- **上手**：空态引导降低新用户认知门槛
- **一致性**：设计 token 单源，后续维护成本下降
