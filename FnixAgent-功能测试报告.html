6. 问题清单与修复建议

P0-01: BYOK API Key 配置源断裂 — Work/Chat 流式功能完全不可用 P0
前端设置面板存储的加密 API Key 未被后端 llm_policy.py:resolve_api_key() 读取。后端只检查 os.getenv() 环境变量，而 .env 中 Key 值已清空。
复现： curl -X POST /api/v1/work/stream -d '{"user_input":"hello"}' -H "Authorization: Bearer $TOKEN" → {"chunk_type":"error","content":"请先在 Desktop 设置中填写您自己的 API Key（Fnix 仅支持 BYOK）"}
修复方向：在 llm_policy.py:resolve_api_key() 中增加从 harness 加密存储读取 Key 的回退路径，或在前端发送 work/stream 请求时附带请求级 llm.api_key（从 localStorage 解密后传入）。
P0-02: 会话恢复失败 — "cannot rebuild messages from events" P0
点击已有会话时，后端无法从事件存储重建消息列表，导致历史会话不可查看。
复现：在侧栏点击任意已有会话 → 页面显示 {"detail":"cannot rebuild messages from events"}
修复方向：检查 harness/session.py 中的 rebuild_messages_from_events() 函数，可能事件序列化格式变更后未做向后兼容。
P0-03: /api/v1/coding/status 返回 404 P0
Code 模式的后端状态端点不存在，前端 Code 模式可能无法正确获取状态。
修复方向：在 api/routers/ 中注册 coding 路由，或确认前端是否使用了不同的端点路径。
P1-01: 侧栏折叠无视觉反馈 P1
点击折叠按钮后，.fnix-side-expand 按钮出现，但 aside 宽度从 260px 未变。可能是 CSS transition 未生效或折叠逻辑仅改变内容不改变容器。
P1-02: 搜索功能 (Ctrl+K) 无输入框 P1
点击搜索按钮后，DOM 中未出现 input[type=search] 或任何搜索输入框元素。可能是搜索组件未渲染或使用了非 input 方案。
P1-03: fnix-local sidecar 不自动启动 P1
后端启动后 work/status 报 degraded=true, fnix_local_offline=true。需手动运行 apps/fnix-local/target/release/fnix-local.exe 才恢复。Tauri 桌面端可能通过进程管理自动拉起，但浏览器预览模式不会。
P1-04: 诊断面板 — 配置目录无法检测 P1
Diagnostics 面板显示"配置目录缺失，重启客户端即可自动生成"。浏览器预览模式下 Tauri 的配置目录逻辑未执行。
P2-01: Skill 库为空 (0 skills) P2
/api/v1/agentos/skill/list 返回空列表。项目代码中有 skill 加载逻辑，但运行时未注册任何 skill。

8. 结论

核心发现：FnixAgent 在基础设施层面（API 路由、认证、安全、UI 框架）已达到较高成熟度， Smoke Test 11/11 通过，安全修复确认有效。但核心功能链路存在阻断级 bug—— BYOK Key 配置源断裂导致 Work/Chat 流式功能完全不可用，会话恢复失败导致用户无法查看历史。

与上轮对比：上一轮代码审计修复后评分为 8.0/10（代码层面）。 本次功能测试暴露了代码审计无法发现的运行时配置断裂问题，回退至 6.8/10。 修复 P0-01（BYOK Key 读取）后预计可恢复至 8.0+，修复 P0-02（会话恢复）后可达 8.5+。

修复优先级：

  1. P0-01（BYOK Key 断裂）— 阻断所有 LLM 功能，必须最先修复
  2. P0-02（会话恢复）— 影响用户体验和连续性
  3. P0-03（coding/status 404）— 影响 Code 模式状态获取
  4. P1-01~04 — UI/UX 打磨，不影响核心功能
