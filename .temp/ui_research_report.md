## 一、各产品 UI 设计要点

### 1. Cursor — AI 原生代码编辑器

**产品定位**：基于 VS Code fork 的 AI 原生 IDE，以 Agent 为中心的工作空间。2026 年 ARR 超 20 亿美元，60%+ 财富 500 强已部署。

#### A. 侧边栏结构
- **沿用 VS Code 四面板布局**：资源管理器（文件树）、搜索、Git 集成、插件扩展
- Activity Bar 最左侧竖列图标切换（Explorer / Search / Source Control / Extensions / **Agent 对话区**）
- **Agent 对话区作为独立面板**，与编辑器平行，非嵌入式弹窗
- Cursor 3 新增 **Agents 窗口**（Agent Command Center），支持本地与云端 Agent 衔接、多仓库支持
- **模式切换不在侧边栏**，而是在聊天面板内（Agent / Plan / Debug / Ask 四种模式）

#### B. Workspace 选择交互
- **通过文件菜单打开文件夹**（VS Code 原生方式），无独立 workspace 选择器
- 多仓库支持是 Cursor 3 新功能：在 Agents 窗口中管理多个 repo
- 无下拉/chip 式 workspace 选择器——工作目录由打开的文件夹决定
- **@ 引用机制**：在聊天框输入 `@filename` 可精准引用文件，替代显式 workspace 切换

#### C. 聊天框区域
- **模式切换在输入框上方**：Agent / Plan / Debug / Ask 四种模式横向排列
- **模型选择在输入框左下角**：下拉选择 SOTA 模型，可选 Auto / Premium / 手动指定
- 支持 `@` 引用文件、拖放图片、拖放文件/文件夹到对话框
- 支持 Skills 预设操作（如图片转 WebP）
- **两种布局**：Agent 布局（AI 优先）和 Editor 布局（编辑器优先），可在设置中切换

#### D. 任务执行过程可视化
- **Composer 模式下**：多文件修改以 diff 预览呈现，Accept/Reject 按钮在每条变更下方
- **Plan 模式**：AI 先输出详细计划（Markdown 格式），用户确认后执行
- **Agent 模式**：自动执行终端命令、创建/修改文件，实时显示操作日志
- 无显式进度条；通过消息流自然展示执行过程
- 支持检查点（checkpoint）回退

#### E. 信息密度控制
- 侧边栏文件树可折叠；聊天面板可全屏/半屏切换
- 历史对话列表在 Agent 面板顶部，可快速切换
- 默认隐藏技术细节（如 token 消耗），需手动展开查看用量
- **关键设计**：Agent 布局下 AI 面板占据更大比例，编辑器区域可收起

### 2. Windsurf / Devin Desktop — Codeium → Cognition 收购后更名

**产品定位**：原 Codeium/Windsurf，2026 年 6 月被 Cognition（Devin 母公司）收购并更名为 Devin Desktop。AI 原生 IDE，以 Cascade（现 Devin Local）为核心交互界面。

#### A. 侧边栏结构
- **双模式架构**：Agent 模式（Agent Command Center）vs Editor 模式，通过 `Ctrl/Cmd+G` 快速切换
- Agent 模式下：侧边栏变为 **Session 会话列表**，按 workspace 分组（Space 概念），支持过滤/排序/分组
- Editor 模式下：恢复 VS Code 标准侧边栏（文件树、搜索、Git）
- **Session tab 使用 pill（圆角药丸）样式**，带状态/PR 图标
- 右键上下文菜单支持重命名、新会话、复制 URL 等

#### B. Workspace 选择交互
- **Agent 位置选择器（Agent Location Selector）**：在聊天框附近选择工作目录
- 支持 **Worktree**（Git 工作树）作为独立工作空间，变更可通过 Merge 按钮合并回主分支
- Space 分组：会话按 workspace 自动归类，支持跨项目隔离
- **Current Workspace 视图**：过滤显示仅当前项目的对话，避免信息干扰

#### C. 聊天框区域
- **Composer 输入区**：支持 @-mention（文件/目录/技能/规则/终端）
- @-mention pills 带类型特定图标（文件图标 vs 目录图标 vs 技能图标）
- **模型选择器**：Cascade 模型选择器中 "Devin Local only" 的模型灰显并带 tooltip
- 输入框支持上下箭头浏览历史提示
- **Editable Command Approvals**：点击权限卡片中的命令可编辑后再批准
- 支持 Queued Messages 编辑（在发送前可修改排队消息）

#### D. 任务执行过程可视化
- **Plan Mode**：AI 先研究（只读命令），生成持久化 Markdown 计划文件（`~/.devin/plans/plan-<session>.md`），用户审核后点 **Implement** 按钮执行
- **Terminal Cards**：终端命令以卡片形式展示，完成后展开显示完整命令和输出
- **Diff Summary**：折叠的 agent group 显示 `+X −Y` 差异摘要，可点击打开多文件 diff 编辑器
- **Permission Cards**：每个需要权限的操作弹出批准卡片，带快捷键提示（always-allow / reject）
- **Subagents 独立停止**：可单独停止某个子 agent 而不取消整个 turn
- **Timeline Navigator**：会话有微妙的时间线导航器

#### E. 信息密度控制
- **Agent Command Center 默认隐藏状态栏**（可通过设置恢复）
- 文件标签有未保存更改指示器
- 会话大小以 chip 形式显示（用 ACU 阈值）
- **Rounded pill session tabs**：圆角药丸式会话标签，紧凑且状态明确
- 大量上下文操作隐藏在 `...` 菜单中

### 3. Trae — 字节跳动 AI IDE

**产品定位**：字节跳动 AI 原生 IDE，基于 VS Code 内核，2026 年 Q2 突破 600 万注册用户，国内免费。

#### A. 侧边栏结构
- **三种模式**：IDE 模式、Builder 模式、SOLO 模式（独立桌面端/网页端）
- IDE 模式：标准 VS Code 布局，AI 面板在右侧
- Builder 模式：从零构建完整项目，AI 主导生成前后端分离项目框架
- SOLO 模式：**独立产品形态**，不依附于编辑器，AI 自主完成编码→调试→测试→部署全流程
- 侧边栏在不同模式下完全重构——SOLO 模式下侧边栏变为任务/会话管理

#### B. Workspace 选择交互
- IDE 模式：标准 VS Code 文件夹打开方式
- SOLO 模式：**项目即 workspace**，新建项目即创建新 workspace
- 无显式 workspace 下拉选择器
- 国内场景优化：直接中文交互，无网络障碍

#### C. 聊天框区域
- **Chat 模式**：智能代码补全、问答、解释代码
- **SOLO 模式**：全自动 AI 开发团队，用户仅需描述需求
- 支持多模型切换（豆包 Seed-2.0-Code 等）
- 中文输入体验优化，提示词中文理解能力强
- **CUE**：Trae 独有的上下文增强机制，在聊天框中引用

#### D. 任务执行过程可视化
- SOLO 模式：**完整工作流可视化**——编码→调试→测试→部署的进度链
- Builder 模式：项目结构生成过程以树状视图展示
- IDE 模式：标准 diff 预览 + Accept/Reject
- **SOLO 独立端**有更丰富的过程展示（类似项目管理看板）

#### E. 信息密度控制
- IDE 模式信息密度与传统 VS Code 一致
- SOLO 模式：**极简界面**，隐藏代码细节，只展示任务进度和结果
- 98% 代码生成准确率（CSDN 评测），减少人工干预

### 4. Cline — VS Code 开源 AI 插件

**产品定位**：开源 AI coding agent，VS Code 插件，BYOK（自带 API Key），5M+ 安装量。

#### A. 侧边栏结构
- **作为 VS Code 扩展嵌入**，在 Activity Bar 中有独立图标
- 点击后打开 **Cline 面板**（Webview 视图），类似聊天界面
- 无独立文件树——共享 VS Code 的资源管理器
- **Focus Chain**：智能任务系统，自动生成清单、实时进度跟踪
- 支持多实例并行工作流（前端/后端/文档可同时运行独立 Cline 实例）

#### B. Workspace 选择交互
- **由 VS Code 的打开文件夹决定**，无独立 workspace 选择器
- @ 引用文件时自动定位到当前 workspace
- 多实例架构下：每个 Cline 实例可绑定不同的工作目录

#### C. 聊天框区域
- **输入框布局**：上方为模式/模型选择，中间为对话区域，底部为输入框
- 支持 K3、Claude、GPT 等多家模型
- **每条消息只能使用一个工具**（结构化协议），用户同意后执行
- 支持 Skills（Claude Skills 规范的具体实现）
- MCP 工具集成

#### D. 任务执行过程可视化
- **逐步工具使用**：每步操作（读文件、执行命令、浏览器操作）都展示为独立卡片
- **Approve / Reject 按钮**：每个工具调用前需用户批准，显示具体操作内容
- **Terminal 输出内联展示**：命令执行结果直接在对话流中显示
- **Browser 操作可视化**：截图展示浏览器操作步骤
- **Task Checklist**：自动生成待办清单，实时勾选完成项
- **Focus Chain 进度跟踪**：任务状态保持，跨上下文持久化

#### E. 信息密度控制
- 工具调用结果可折叠/展开
- 终端命令默认显示摘要，点击展开完整输出
- 文件修改以 diff 形式展示，可逐文件查看
- **核心设计**：每一步操作都需用户确认（除非开启 auto-approve），控制感极强

### 5. GitHub Copilot Chat

**产品定位**：GitHub 官方 AI 编程助手，市场覆盖最广，支持 VS Code/JetBrains/Visual Studio/Xcode 等主流编辑器。

#### A. 侧边栏结构
- **嵌入 VS Code Activity Bar**，点击打开 Copilot Chat 面板
- 支持 Inline Chat（编辑器内联对话，`Alt+I`）
- **Workspace 功能**：跨仓库检索上下文，对大型 Monorepo 支持较好
- 2026 年 8 月已接入多模型（Kimi K3 等），可在多模型间选择

#### B. Workspace 选择交互
- **隐式上下文**：Copilot 自动感知当前打开的文件、选中的代码
- **@ 参考机制**：`@workspace`（整个工作区）、`@file`（特定文件）、`@terminal`（终端输出）
- 支持图像附件作为额外上下文
- 聊天记录管理：SESSIONS 侧边栏显示历史会话

#### C. 聊天框区域
- **模型选择**：在聊天面板中可切换模型
- **Ask / Edit / Agent 模式**：2026 年起转向 AI Credits 计费
- 补全免费（不计积分），Chat 和 Agent 按用量扣积分
- 支持参考（References）：将对话范围限定于特定文件、变更和提交记录
- 隐式上下文 + 显式参考双机制

#### D. 任务执行过程可视化
- **Agent 模式**：逐步执行任务，显示操作日志
- **Edit 模式**：直接在编辑器中展示 diff，接受/拒绝变更
- **Ask 模式**：纯问答，不修改代码
- 进度展示较简洁，依赖 VS Code 原生通知和状态栏

#### E. 信息密度控制
- 隐式上下文不显示（用户无感知），减少干扰
- 显式参考以 chip/pill 形式展示在输入框上方
- 内联补全以灰色文本预览，Tab 接受

### 6. v0.dev / v0.app — Vercel AI 生成器

**产品定位**：Vercel 出品的前端 UI 生成工具，自然语言描述 → React + Tailwind + shadcn/ui 代码。2025 年 8 月升级为 v0.app，具备全栈智能体能力。

#### A. 侧边栏结构
- **纯 Web 界面**，无传统 IDE 侧边栏
- 左侧为 **项目/对话历史列表**
- 中间为 **聊天 + 实时预览** 双栏
- 右侧为 **代码编辑器**（可切换查看生成的代码）
- 无文件树——v0 管理整个项目结构

#### B. Workspace 选择交互
- **项目即 Workspace**：每个对话/项目独立
- 新建项目 = 新 workspace，通过左侧列表切换
- 无传统文件夹概念——以生成内容为单位组织

#### C. 聊天框区域
- **输入框在底部中央**，简洁的聊天式交互
- 支持自然语言描述 UI 需求
- **实时预览**：聊天过程中右侧即时显示生成的 UI
- 支持多框架输出（React / Vue / Svelte）
- 默认适配 shadcn/ui + Tailwind CSS

#### D. 任务执行过程可视化
- **代码生成过程**：流式输出，逐行展示生成代码
- **实时预览**：生成过程中 UI 实时更新
- 无传统进度条——通过代码流和预览变化自然感知进度
- 支持 **迭代式修改**：在预览基础上用自然语言继续调整

#### E. 信息密度控制
- **极简设计**：只有聊天 + 预览，无多余面板
- 代码可折叠查看，默认展示预览
- 项目历史以卡片形式展示
- **信息分层**：预览优先 > 代码次之 > 历史最后

### 7. bolt.new — StackBlitz AI 全栈生成

**产品定位**：浏览器内直接生成、运行、部署全栈应用。支持 React、Vue、Node 等主流框架。

#### A. 侧边栏结构
- **纯 Web 界面**
- 左侧：项目列表/历史
- 中间偏左：**聊天对话区**
- 中间偏右：**实时预览区**（WebContainer 运行时）
- 右侧/底部：**代码编辑器**（Monaco Editor）
- 无传统文件树——但生成的项目结构可查看

#### B. Workspace 选择交互
- **每个聊天即一个独立项目**
- 新建聊天 = 新 workspace
- 通过左侧项目列表切换
- 支持一键部署到 Netlify 等平台

#### C. 聊天框区域
- **底部输入框**，简洁聊天式
- 支持自然语言描述需求
- 生成过程中可继续输入修改指令
- 模型选择不明显（默认使用内置模型）

#### D. 任务执行过程可视化
- **聊天流 + 代码流 + 预览流三路并行**
- 代码生成时：编辑器高亮新增/修改的文件
- **终端输出**：依赖安装、构建过程实时展示
- 预览区实时更新
- 无显式进度条——通过多区域变化自然感知

#### E. 信息密度控制
- **三栏布局**（聊天 + 预览 + 代码），可调整比例
- 默认聚焦预览区
- 代码区可全屏展开
- 终端输出可折叠

### 8. Replit Agent — 云端 AI 编程

**产品定位**：老牌云端 IDE + AI Agent 功能。多智能体架构，Claude 3.5 Sonnet 模型，面向非技术背景用户。

#### A. 侧边栏结构
- **云端 IDE 布局**：左侧文件树，中间编辑器，右侧 AI 面板
- Agent 3 具备更高自主性：测试并修复代码
- 移动端支持较好
- 支持多语言和部署

#### B. Workspace 选择交互
- **Repl 即 Workspace**：每个项目是一个 Repl
- 通过 Dashboard 创建/切换 Repl
- 支持 Template 选择（从模板创建）
- 无显式 workspace 下拉——以项目为单位

#### C. 聊天框区域
- **右侧 AI 面板**
- 自然语言描述需求 → 自动生成代码、配置环境、安装依赖、配置数据库、部署
- 多智能体架构：不同 agent 负责不同子任务

#### D. 任务执行过程可视化
- **全流程可视化**：从代码生成 → 开发环境设置 → 软件包安装 → 数据库配置 → 应用部署
- 每个步骤有状态指示
- Agent 3 可自主测试并修复代码

#### E. 信息密度控制
- 云端 IDE 信息密度较高
- AI 面板可折叠/展开
- 适合教育场景和协作编程

### 9. Aider — 终端 AI 编程

**产品定位**：纯终端 CLI 工具，GitHub Star 18k+，纯 Python 实现，支持几乎所有主流 LLM。

#### A. 侧边栏结构
- **无 GUI 侧边栏**——纯终端界面
- 终端内显示：对话流 + 文件修改 diff + Git 提交信息
- 支持多文件协同编辑
- Git 集成：自动提交代码变更

#### B. Workspace 选择交互
- **由启动时的 `cd` 目录决定**
- `aider` 命令在当前目录启动
- 可使用 `/add` 和 `/drop` 命令动态添加/移除文件到上下文
- 无下拉/chip——纯命令行交互

#### C. 聊天框区域
- **终端底部输入区**，类似 REPL
- 支持斜杠命令（`/add`、`/drop`、`/ask`、`/code` 等）
- 支持上下文管理命令
- 系统提示词定制

#### D. 任务执行过程可视化
- **diff 直接在终端输出**，以颜色区分增/删行
- Git commit 信息展示
- 无进度条——通过输出流自然感知
- 支持批量操作脚本

#### E. 信息密度控制
- **极简**：只有文本输出
- 可控制输出详细程度（`--verbose` 选项）
- 文件修改默认显示 diff 摘要
- 上下文使用量可查看

### 10. OpenHands — 开源 AI Agent

**产品定位**：开源 AI 驱动开发平台（原 OpenDevin），支持代码理解、编辑、终端操作、浏览器交互。基于 CodeAct 交互式多轮流程。

#### A. 侧边栏结构
- **Web UI 界面**：左侧会话/项目列表，中间工作区，右侧 AI 面板
- **Microagents**：一组量身定制的指令模块，给工具注入更聚焦的能力
- 支持多智能体（multi-agent）架构
- 可自定义 agent 行为

#### B. Workspace 选择交互
- **通过 Web UI 选择/创建工作区**
- 支持 Docker 容器隔离的沙箱环境
- 无传统文件树——由 agent 管理
- workspace 与会话绑定

#### C. 聊天框区域
- **Web 界面聊天框**
- 支持自然语言交互
- CodeAct 协议：agent 通过代码行动（CodeAct）与环境交互
- 多轮对话流程

#### D. 任务执行过程可视化
- **交互式多轮流程**：agent 接收观察数据 → 优化行动方案 → 执行
- 终端操作、浏览器操作、文件编辑均可可视化
- **Canvas**（类 OpenClaw）：Agent 驱动的可视化工作区
- 操作步骤以消息流展示

#### E. 信息密度控制
- 操作日志可折叠
- 不同类型操作（代码/终端/浏览器）可分类过滤
- 支持 Microagents 按需加载，减少无关信息

## 三、对 FnixAgent 的具体优化建议

### 建议总览

基于对 10 款 AI 编程工具的深度调研，结合 FnixAgent 当前的前端架构（Next.js 16 + React 19 + Tailwind v4 + shadcn/ui）和已有的过程可视化组件（ProcessTimeline、ThinkingBlock），提出以下优化方案：

### 优化 1：侧边栏精简方案

**现状问题**：FnixAgent 侧边栏可能存在信息密度过高、功能模块堆叠的问题。

**参考方案**：

#### 方案 A：Windsurf/Devin 双模式架构（推荐）
```
┌──────────────────────────────────────────────────┐
│ [Agent模式]  │  [Editor模式]  │  ← Ctrl/Cmd+G 切换 │
├──────────────┼───────────────────────────────────┤
│              │                                   │
│  Session     │     AI 聊天区 / 编辑区             │
│  会话列表    │                                   │
│  (按workspace│     ┌─────────────────────────┐  │
│  分组)       │     │  消息流 / 过程可视化     │  │
│              │     │                         │  │
│  Space A     │     │  ThinkingBlock          │  │
│  ├ session1  │     │  ProcessTimeline        │  │
│  ├ session2  │     │                         │  │
│              │     └─────────────────────────┘  │
│  Space B     │     ┌─────────────────────────┐  │
│  ├ session3  │     │  输入框                  │  │
│              │     │  [模型选择] [模式] [@]   │  │
│  + 新会话    │     └─────────────────────────┘  │
└──────────────┴───────────────────────────────────┘
```

**具体实施**：
1. **左侧栏仅保留 Session 列表**，按 workspace 分组（Space 概念），用 **pill 样式标签**（参考 Windsurf）
2. 文件树/试卷/错题本等功能模块移到 **顶部标签栏** 或 **右侧面板**
3. 每个会话标签带状态图标（进行中/完成/需输入）
4. 右键上下文菜单支持重命名、新会话、删除

#### 方案 B：Cursor Agent 面板优先布局
- 左侧保持精简导航（仅图标列），点击展开对应功能
- AI 面板占据更大比例，功能模块作为面板内 tab

### 优化 2：Workspace 选择移到聊天框

**现状问题**：当前 workspace/科目/试卷 选择可能在侧边栏，与聊天交互分离。

**参考方案**（综合 Windsurf Agent Location Selector + Copilot @workspace + Cursor @引用）：

```
┌──────────────────────────────────────────────────┐
│  AI 聊天区                                       │
│                                                  │
│  [消息流...]                                     │
│                                                  │
│  ┌────────────────────────────────────────────┐  │
│  │ [📐 高中数学 ▾] [🤖 DeepSeek-V4 ▾] [@📎]  │  │
│  │ ┌────────────────────────────────────────┐ │  │
│  │ │ 输入你的问题...                        │ │  │
│  │ │                                        │ │  │
│  │ └────────────────────────────────────────┘ │  │
│  │ [发送] [模式: 辅导 ▾] [附件] [语音]       │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

**具体设计**：
1. **Workspace Chip（工作区选择器）**：在输入框左上方放置 chip 式下拉选择器
   - 参考 Windsurf 的 Agent Location Selector
   - 显示当前工作区（如"高中数学"、"错题本-代数"）
   - 点击展开下拉列表，支持搜索
   - 支持"最近使用"和"固定"分组

2. **模型选择器**：紧邻 Workspace Chip，下拉选择
   - 参考 Cursor 的模型选择器位置（输入框左下角）
   - 显示当前模型名称 + 速度/能力标签

3. **模式选择器**：在输入框右下方
   - 辅导模式（默认，脚手架提示不直接给答案）
   - 讲解模式（详细解析）
   - 测试模式（生成测试题）
   - 参考 Cursor 的 Agent/Plan/Debug/Ask 模式切换

4. **@ 引用机制**：
   - `@题目` 引用特定题目
   - `@知识点` 引用知识点
   - `@错题本` 引用错题本
   - 参考 Cursor 和 Copilot 的 @-mention 系统

### 优化 3：过程可视化改进

**现状**：已有 `ProcessTimeline`（rAF + scrollTo smooth）和 `ThinkingBlock`，存在"planning/executing" 文本拼接问题。

**参考方案**（综合 Windsurf Terminal Cards + Cline Task Checklist + Trae SOLO 流程链）：

#### 3.1 分阶段卡片式展示
```
┌──────────────────────────────────────────────────┐
│  📋 理解问题                          ✅ 完成   │
│  ├ 分析题目类型：极限求解                       │
│  └ 识别关键概念：等价无穷小                     │
│                                                  │
│  🧠 思考过程                          ✅ 完成   │
│  ├ 判断题型：1^∞ 型极限                         │
│  ├ 选择方法：等价无穷小替换                     │
│  └ 自我检查：验证替换条件                       │
│                                                  │
│  💡 引导提示                          ⏳ 进行中 │
│  ├ 第一步提示：...                              │
│  └ 第二步提示：...                              │
│                                                  │
│  ✅ 教学反思                          ⬜ 待开始 │
└──────────────────────────────────────────────────┘
```

**具体设计**：
1. **阶段卡片**：每个阶段（理解/思考/引导/反思）独立卡片，带状态图标
   - 参考 Cline 的 Task Checklist（自动生成清单、实时进度跟踪）
   - 参考 Trae SOLO 的全流程链可视化

2. **可折叠详情**：
   - 默认显示阶段标题 + 状态
   - 点击展开查看详细内容
   - 参考 Windsurf 的 Terminal Cards（完成后展开完整输出）

3. **消除文本拼接问题**：
   - 每个阶段独立渲染组件，不拼接 description 字段
   - 使用独立的 `phase` / `step` / `status` 字段
   - 参考 Cline 的逐步工具卡片设计（每步独立）

#### 3.2 进度指示器
```
  ●━━━●━━━●━━━○━━━○
  理解  思考  引导  反思  总结
```
- 水平进度条，节点对应阶段
- 当前阶段脉冲动画（已有 `fnixNodePulse`）
- 已完成节点实心，未开始空心
- 参考 Trae SOLO 的进度链

#### 3.3 用户控制点
- **Pause/Resume 按钮**：长任务可暂停/继续
- **Approve/Reject**：关键步骤前需确认（参考 Cline）
- **跳过当前阶段**：用户可选择跳过某阶段
- 参考 Windsurf 的 Subagent 独立停止功能

### 优化 4：信息密度控制策略

| 信息类型 | 展示位置 | 展示方式 | 默认状态 |
|---------|---------|---------|---------|
| 当前模型 | 输入框上方 chip | 文字 + 图标 | 始终显示 |
| 当前 workspace | 输入框上方 chip | 文字 + 图标 | 始终显示 |
| 当前模式 | 输入框下方 | 文字 + 图标 | 始终显示 |
| 思考过程 | 消息流内 | 可折叠卡片 | 默认折叠 |
| 任务进度 | 消息流顶部 | 进度条/节点链 | 始终显示 |
| 文件变更 | 消息流内 | diff 预览 | 默认折叠 |
| 终端输出 | 消息流内 | 代码块 | 默认折叠 |
| 历史会话 | 侧边栏 | 列表 | 可隐藏 |
| 用量统计 | 设置面板 | 图表 | 隐藏 |
| 技术细节 | tooltip | 悬浮提示 | 隐藏 |

**核心原则**（参考 Windsurf/Cursor）：
- **预览优先 > 代码次之 > 历史最后**（参考 v0.dev）
- **隐式上下文不显示**（参考 Copilot Chat）
- **操作日志可折叠**（参考 Cline）
- **关键操作需确认**（参考 Cline 的 Approve/Reject）

   - `@题目`、`@知识点`、`@错题本` 引用
   - 参考 Cursor 的 @-mention 系统

### P2 — 中期执行（锦上添花）

7. **阶段卡片式过程展示**
   - 理解/思考/引导/反思分阶段卡片
   - 状态图标 + 可折叠详情
   - 参考 Cline Task Checklist

8. **进度节点链**
   - 水平进度条，阶段对应节点
   - 当前阶段脉冲动画

9. **Plan 模式**
   - 复杂问题先出教学计划，确认后执行
   - 参考 Cursor Plan Mode 和 Windsurf Plan Mode

### P3 — 长期演进

10. **双模式架构**
    - AI 辅导模式 vs 编辑/管理模式
    - 参考 Windsurf 的 Agent/Editor 双模式

11. **多实例并行**
    - 不同科目/任务并行运行独立 AI 会话
    - 参考 Cline 多实例

12. **可编辑批准**
    - AI 建议/提示可编辑后再应用
    - 参考 Windsurf 的 Editable Command Approvals

## 六、总结

| 维度 | 最佳参考 | FnixAgent 应用方向 |
|------|---------|-------------------|
| 侧边栏精简 | Windsurf（Session列表 + Space分组） | 左侧仅保留会话列表，功能模块移到顶栏 |
| Workspace 选择 | Windsurf（Agent Location Selector）+ Cursor（@引用） | 聊天框上方 chip 选择器 + @引用机制 |
| 聊天框设计 | Cursor（模式+模型+@+拖放） | 输入框上方 workspace+模型 chip，下方模式选择 |
| 过程可视化 | Cline（Task Checklist）+ Trae SOLO（流程链）+ Windsurf（Terminal Cards） | 分阶段卡片 + 进度节点链 + 可折叠详情 |
| 信息密度控制 | v0.dev（预览优先）+ Windsurf（折叠+pill） | 预览/结果优先，技术细节可折叠，pill 式标签 |
| 用户控制感 | Cline（每步Approve/Reject） | 关键步骤前确认，可编辑建议 |

> **核心理念**：FnixAgent 作为 AI 教育产品，应参考 AI 编程工具的 **过程可视化** 和 **用户控制感**，同时结合教育场景的 **脚手架提示** 理念——让学生看到 AI 的思考过程，在关键步骤有选择权，而非直接给出答案。
